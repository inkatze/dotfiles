- 2026-09-10 [dotfiles] neovim is removed from this repo; a replacement editor is expected later. Gone with it: `roles/neovim/` and its tracked config, the `- neovim` role entry in `main.yml`, the `mise run neovim` task, the CI matrix entry, the README and CLAUDE.md sections, the Brewfile's jdtls / efm-langserver / stylua, and the editor-only default packages (`neovim` gem; `neovim`, `mcp-hub` and `vim-language-server` npm; `neovim`, `pynvim` and `msgpack` python). `lua-language-server` was removed and then restored: `roles/claude/files/settings.json` enables the lua-lsp Claude Code plugin, which shells out to it, so the editor was never its only consumer. The fish aliases `vi`, `nv`, `nvh` and `nvi` are deleted; `v`, `vim` and `nv` now point at `vi`, as do EDITOR and git's core.editor — `vi` rather than `vim` because the Linux host carries only vim.tiny, exposed as /usr/bin/vi, and macOS ships /usr/bin/vi too. `nv` had to come back because `roles/fish/files/fish/functions/tm.fish` types that literal string into eight tmux panes. `vim-tiny` is now declared in `linux_apt_packages`: the editor used to be guaranteed by the playbook that installed it, and naming a binary nothing provisions gave that up silently. Note what this does NOT do: nothing is uninstalled anywhere. The removals are un-declarations, so the Macs keep their nvim install, PATH symlink, plugin tree and the four Brewfile packages, and `~/.config/nvim` dangles on every host that ran the old role; only this Linux host was cleaned, by hand. Per the historical-record convention prior entries stay as written, but four are now moot or wrong: 2026-08-19-tooling-gap-a5ad218e (stylua vs roles/neovim's lua files; settled by dropping the tool), 2026-08-19-ci-idempotency-765be2e1 (the neovim role's CI entry could go strict), 2026-08-19-third-party-home-assumption-58c66feb (elixir-tools.nvim, upstream in a plugin no longer pinned), and 2026-08-10-claude-role-has-no-mise-task-or-ci-entry-4c06f01f, whose CI-matrix enumeration no longer lists neovim.
