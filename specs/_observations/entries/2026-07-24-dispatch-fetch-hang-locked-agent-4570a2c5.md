- 2026-07-24 [dotfiles] orchestrate/dispatch-fetch: the freshness-gate git fetch (git -C <repo> fetch origin) has no timeout, so when the 1Password SSH agent was locked after a machine restart (SSH remote git@github.com, no keys to auth), the fetch blocked indefinitely INSIDE the per-spec lock window (lock acquired, fetch hung >120s, moved to background). A hung fetch holding the lock can wedge a tower until the operator intervenes. Consider bounding dispatch-fetch.sh (and the reconcile best-effort fetch) with a git-level timeout (e.g. GIT_HTTP_LOW_SPEED_* / a wrapper kill after N seconds) and/or a pre-flight non-blocking auth probe (git ls-remote with ConnectTimeout+BatchMode) so a locked/absent SSH agent fails the gate cleanly to Awaiting input rather than hanging with the lock held. Observed 2026-07-23 on crojtini; resolved once the operator unlocked 1Password.
