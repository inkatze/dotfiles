- 2026-08-05 [dotfiles] fleet-streamjson.sh recover leaves a silently hung worker when the prior worker was killed while a permission control_request was pending. recover relaunches with --resume but writes a ZERO-BYTE initial-message file, so with `claude -p --input-format stream-json` the resumed process replays the session and then blocks on stdin forever with no turn to take. The in-flight tool call that would have continued the turn is gone, killed with the old process. Meanwhile `fleet-streamjson.sh status` reports `running` (the pid is genuinely alive), the journal shows no new blocks, and nothing anywhere reports the stall: observed 36 minutes of total silence read as healthy progress. Detect it by events.jsonl mtime and the init-event count (a resumed worker should emit a second init; the hung one emitted none), not by status or the block journal. Workaround that does work: relaunch with `launch` passing both a real prompt file and `-- --resume <session_id>`, which resumes the session AND supplies a user turn.
