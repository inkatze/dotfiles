- 2026-08-10 [dotfiles] A change to a slash command cannot be dogfooded through that slash command from a worktree. ~/.claude/commands symlinks to the MAIN checkout (roles/claude/files/commands), so the skill loader serves main version regardless of which worktree the session is in; the same applies to ~/.config/mise/conf.d/linux.toml, so a mise pin added in a worktree is not live either. Observed while running /panel-review --nested against a branch that changes /panel-review: the loaded instructions were the pre-change ones, and the review had to follow the worktree copy by hand. Worth a documented workaround (a temporary symlink flip, or a note in the Adding a new Claude command section) since testing command changes before merge is exactly when you want them live.
