- 2026-08-06 [dotfiles] The mise-managed Erlang 28.3 on the Linux host is built without OpenSSL: its lib/ carries no `crypto` and no `ssl` application, so `crypto:strong_rand_bytes/1` is undefined. Consequences are broad, not cosmetic — `mix deps.get`, `Mix.install/1` and anything reaching hex.pm over TLS all fail, so no Elixir project on this host can resolve a dependency, and the repo declares erlang and elixir in roles/environments as if it could. Surfaced while executing specs/dev-services Task 4, whose Done-when needs the consuming stack Redis client run against a live server; that clause was answered by fetching and compiling the pinned library directly, which works but is a workaround. Likely cause is a kerl/source build that ran without libssl-dev present. Belongs to whichever bundle owns the environments role rather than to dev-services.
